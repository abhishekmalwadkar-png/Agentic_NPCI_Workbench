# NPCI Unified Operations Workbench

## Autonomous 4-Way Reconciliation, AI Exception Investigation, and GRC Operations Platform

The NPCI Unified Operations Workbench is an enterprise-grade banking operations platform designed to automate end-to-end clearing file validation, multi-rail reconciliation, root-cause exception investigation, and regulatory compliance reporting across major Indian payment rails.

Built to comply with the Reserve Bank of India (RBI) Harmonisation of Turn Around Time (TAT) and customer compensation directives (T+1 turnaround requirements), this platform eliminates manual swivel-chair operations by orchestrating RPA bots, rule engines, deterministic matching algorithms, and autonomous AI agents into a unified operations fabric.

---

## Key Capabilities

- Multi-Rail Ingestion: Native validation and normalization across UPI, IMPS, RTGS, NACH, AePS, RuPay, BBPS, and NETC FASTag.
- 4-Way Multi-Leg Reconciliation: High-throughput matching across NPCI Master Settlement, Payment Switch (Base24/Fiserv), Core Banking (Finacle/Flexcube), and General Ledger (GL Suspense Pool).
- Real-Time Batch Ingestion: Universal parser supporting CSV, TXT, TSV, DAT, and Excel (XLSX, XLS BIFF8) formats generated by RPA engines like AutomationEdge Process Studio.
- Autonomous AI Investigation: Auto-diagnoses deemed failures, beneficiary timeouts, amount mismatches, unreversed CBS debits, and generates immutable audit dossiers.
- Dual-Track HITL Governance: Straight-Through Processing (STP) auto-execution for low-risk exceptions alongside a four-eyes Human-in-the-Loop approval cockpit for high-value exposures.
- Regulatory Compliance: Continuous T+1 SLA countdown clocks, financial risk tracking, and exportable RBI compliance evidence packages.

## 6-Stage Architecture

```
[ Settlement Files ] ---> [ Stage 1: File Intake & Validation ]
                                     |
                                     v
                          [ Stage 2: 4-Way Recon Engine ]
                                     |
             +-----------------------+-----------------------+
             |                                               |
             v                                               v
    [ Matched STP (85-95%) ]                      [ Unmatched Breaks (5-15%) ]
             |                                               |
             v                                               v
    [ Auto-Settled ]                              [ Stage 3: AI Investigation Agent ]
                                                             |
                                                             v
                                                  [ Stage 4: HITL Cockpit ]
                                                             |
                                                             v
                                                  [ Stage 5: Recovery & Execution ]
                                                             |
                                                             v
                                                  [ Stage 6: Audit & GRC Evidence ]
```

### Stage 1: File Intake and Staging Vault
- SFTP and directory watcher monitoring inbound settlement feeds.
- SHA-256 cryptographic hashing to prevent duplicate file ingestion.
- Schema verification, rail code checking, and malformed row detection.
- Clean routing to Staging Vault or Rejected Vault with full audit logging.

### Stage 2: 4-Way Multi-Rail Reconciliation Engine
- Deterministic 4-way matching on transaction reference keys (RRN, UTR, Txn ID, Account Number).
- Evaluates four independent operational legs:
  - Leg 1: NPCI Master Settlement Report
  - Leg 2: Payment Switch Logs (Base24)
  - Leg 3: Core Banking System (Finacle / Flexcube)
  - Leg 4: General Ledger Accounts (Suspense Pool)
- Classifies records into Matched STP, In-Flight Timing Differences, and Unmatched Breaks.
- Quantifies net financial variance across CBS, GL, and NPCI settlement figures.

### Stage 3: Autonomous AI Investigation Agent
- Automatically analyzes un-reconciled breaks.
- Categorizes exceptions by root-cause:
  - CBS_DEBIT_NPCI_FAIL: Customer debited, but switch or NPCI declined.
  - NPCI_SUCCESS_CBS_PENDING: NPCI cleared, but CBS leg timed out or failed.
  - AMOUNT_MISMATCH: Partial debits or decimal truncation between switch and CBS.
  - BENEFICIARY_NOT_FOUND: Closed account or invalid IFSC rejection at beneficiary bank.
  - DEEMED_FAIL: System malfunction during inter-bank settlement.
  - REVERSAL_MISSING: Transaction failed with un-triggered customer refund.
- Generates structured investigation dossiers with evidence traces and recommended actions.

### Stage 4: HITL Approvals and Cockpit
- Tiered risk approval routing:
  - P1 High Risk (amount > threshold or T+1 clock running): Requires human maker-checker sign-off.
  - P2 Moderate Risk: Auto-approved for next-cycle roll forward or automated retry.
- Displays side-by-side leg comparison and dossier evidence to operators.

### Stage 5: Recovery, Reversal, and Execution
- Dispatches automated reversal requests to CBS for customer refund.
- Executes balancing journal entries against General Ledger suspense accounts.
- Transmits dispute and chargeback notifications to NPCI clearing portals.

### Stage 6: Audit Evidence and GRC Reporting
- Chronological, tamper-evident audit trail capturing every state transition and API call.
- Generates MIS summary reports and RBI circular compliance export artifacts.

## Supported Payment Rails

| Rail Code | Rail Name | Settlement Cycle | Primary Key | Typical SLA |
| :--- | :--- | :--- | :--- | :--- |
| UPI | Unified Payments Interface | Hourly / Net Cycle | RRN (12 Digits) | T+1 |
| IMPS | Immediate Payment Service | 24x7 Real-Time | RRN / Txn ID | T+1 |
| RTGS | Real Time Gross Settlement | Real-Time Continuous | UTR (22 Chars) | T+0 |
| NACH | National Automated Clearing House | Daily Batch Cycles | Mandate / UMRN | T+1 / T+2 |
| AePS | Aadhaar Enabled Payment System | Daily Clearing | STAN / RRN | T+1 |
| RuPay | RuPay Card Clearing | Multi-Cycle Clearing | Retrieval Ref No | T+1 |
| BBPS | Bharat Bill Payment System | Cycle Settlement | Biller Txn ID | T+1 |
| NETC | FASTag Electronic Toll Collection| Daily Batch Clearing | Tag ID / Txn ID | T+1 |

## Getting Started

### Prerequisites

- Python 3.10 or higher
- Node.js 18 or higher with npm
- Git

### 1. Clone the Repository

```bash
git clone https://github.com/abhishekmalwadkar-png/Agentic_NPCI_Workbench.git
cd Agentic_NPCI_Workbench
```

### 2. Backend Setup

```bash
# Navigate to backend directory
cd stage1/backend

# Install required Python dependencies
pip install fastapi uvicorn aiofiles pandas openpyxl xlrd pydantic

# Start the API server
python -m uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

The backend API will be operational at `http://localhost:8000`. Interactive OpenAPI documentation is available at `http://localhost:8000/docs`.

### 3. Frontend Setup

In a new terminal:

```bash
# Navigate to frontend directory
cd stage1-ui

# Install dependencies
npm install

# Start Vite development server
npm run dev
```

The Workbench Dashboard will be accessible at `http://localhost:5173`.

## Process Studio (AutomationEdge RPA) Integration

The platform is designed to interface with AutomationEdge Process Studio workflows:

1. Workflow Configuration:
   - Configure input steps pointing to the source settlement files (NPCI Master, Payment Switch, Core Banking Finacle, General Ledger).
   - Use Merge Join and Sort steps to align records on the primary reference number (RRN).
   - Route records through rule evaluation to identify matched records vs breaks.
2. Output Configuration:
   - Route matched records to `D:\NPCI-Workbench\stage1\Matched_Records\` using Text file output or Microsoft Excel Output.
   - Route breaks to `D:\NPCI-Workbench\stage1\Unmatched_Records\` using Text file output or Microsoft Excel Output.
3. Supported Output File Formats:
   - Text files: `.txt`, `.csv`, `.tsv`, `.dat` (semicolon `;`, comma `,`, or tab `\t` delimited).
   - Excel files: `.xlsx`, `.xls` (BIFF8 Excel 97-2003 or OpenXML).
4. Automated Ingestion:
   - The Workbench detects and parses new files in both folders automatically within 4 seconds.
   - Multiple batches accumulate seamlessly while deduplicating by transaction RRN.

## Core API Endpoints

| Method | Endpoint | Description |
| :--- | :--- | :--- |
| GET | `/api/stats` | Global processing metrics, file counters, and pipeline status |
| POST | `/api/upload` | Ingests clearing file, runs 6 validation gates, and stages file |
| GET | `/api/recon/summary` | Real-time 4-way reconciliation totals, STP rates, and break breakdown |
| GET | `/api/recon/breaks` | List of un-reconciled breaks filtered by priority or scenario |
| GET | `/api/recon/matched` | List of matched straight-through transactions |
| POST | `/api/recon/run` | Triggers immediate reconciliation execution across active batches |
| GET | `/api/agent/investigate/summary` | Root-cause analysis metrics and generated dossiers |
| GET | `/api/hitl/queue` | Human-in-the-Loop approval queue for P1 exceptions |
| POST | `/api/hitl/approve/{txn_id}` | Approves customer reversal and triggers ledger journal entry |
| GET | `/api/audit` | Chronological audit trail of all platform events |
| POST | `/api/system/clear-all` | Resets caches and physical directories to standby state |
